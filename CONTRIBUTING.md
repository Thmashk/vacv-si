# Как работаем вместе

У каждого участника свой ассистент, и все они правят один репозиторий.
Чтобы агенты не перезаписывали работу друг друга, действуют три правила:
**своя ветка, свои файлы, зелёные тесты перед слиянием**.

Правила для самих ассистентов лежат в `CLAUDE.md` — его Claude Code читает
автоматически при запуске в папке проекта. Отдельно пересказывать агенту
условия задачи не нужно.

## Подключение, один раз

```bash
git clone https://github.com/Thmashk/vacv-si.git
```

```bash
cd vacv-si && make env
```

Файлы Kaggle в репозиторий не входят: по правилам соревнования данные нельзя
передавать за его пределы. Скачайте `train_v2.csv`, `test.csv` и
`sample_submit.csv` со страницы Data и положите в `data/raw/`.

`make env` заодно включает git-хук, который блокирует прямой пуш в `main` и
гоняет тесты перед отправкой. Если окружение уже стоит, включите его
отдельно:

```bash
make hooks
```

Проверка, что всё встало:

```bash
make test
```

Перед первым коммитом настройте почту, иначе GitHub не свяжет ваши коммиты
с профилем и в истории не будет видно вашего вклада:

```bash
git config user.email "ВАШ_ID+ВАШ_НИК@users.noreply.github.com"
```

Свой адрес найдёте в **Settings → Emails → Keep my email addresses private**.

## Кто какие файлы трогает

| Роль | Файлы |
|---|---|
| R1 Капитан | `Makefile`, `src/config.py`, `src/make_submission.py`, `submissions/`, веса ансамбля |
| R2 Данные-1 | `src/collect/chembl_vacv.py`, `src/data/build_dataset.py` |
| R3 Данные-2 и QA | `src/collect/pubchem_vacv.py`, `src/data/validate_dataset.py`, `SOURCES.md`, `DATASET_CARD.md` |
| R4 Классический ML | `src/features.py`, `src/models.py`, `src/cv.py` |
| R5 Питч и документация | `README.md`, `reports/`, слайды |

`tests/` правит тот, кто меняет поведение. Если нужен чужой файл, напишите
владельцу в чат команды и дождитесь ответа — иначе будет конфликт слияния
в самый неподходящий момент.

## Цикл работы

```bash
git switch -c r4/tail-features
```

Дальше обычная работа, затем:

```bash
make test && git add -A && git commit -m "описание" && git push -u origin HEAD
```

```bash
gh pr create --fill
```

Ревью делает другой человек, слияние в течение часа. Без зелёных тестов
не сливаем. После слияния:

```bash
git switch main && git pull && git branch -d r4/tail-features
```

## Именование веток

`r1/` … `r5/` по роли, дальше короткое описание латиницей:
`r2/chembl-collector`, `r4/known-antivirals`, `r1/ensemble-weights`.

## Журнал сабмитов

Каждая отправка на Kaggle — строка в `submissions/log.csv`: время, коммит,
конфигурация, CV, LB, комментарий. Файл обновляется сам при запуске
`make submit`, колонку LB дописывает R1 руками после отправки.

Результат без записи в журнал не считается: его нельзя воспроизвести.

## Чего не делаем

* Не пушим в `main` напрямую.
* Не меняем сиды в `src/config.py`.
* Не коммитим файлы Kaggle, `.venv` и большие выгрузки API.
* Не ищем вручную значения SI для молекул из теста.
* Не трогаем `CC50_uM` и `IC50_uM_VACV` — причины в `CLAUDE.md`.

# Инструкции для ассистента

Этот файл читает Claude Code у каждого участника команды. Он описывает
проект, факты про данные и правила работы. Если факт здесь противоречит
тому, что вы помните, прав этот файл.

## Задача

Хакатон: по SMILES предсказать индекс селективности малых молекул против
вируса осповакцины (VACV). `SI = CC50 / IC50`, обе величины в мкМ.
Метрика — **MSE на исходном SI**, логарифм к ответу не применяется.
Сабмит: CSV с колонками `index,SI VACV`.

Дедлайн: воскресенье 8 ноября, 09:00 МСК. Жёсткая заморозка в 08:00.

## Запрещено правилами

Колонки `CC50_uM` и `IC50_uM_VACV` **нельзя использовать** ни как признаки,
ни для предсказания: из них SI получается делением. Обе присутствуют и в
`train_v2.csv`, и в `test.csv`. Их использование означает дисквалификацию.

Защита: всё читается только через `src.data.load_competition`, которая
удаляет эти колонки. `tests/test_guard.py` падает, если имя всплыло в
признаках. Функция `load_competition_unsafe` существует только для EDA, и
тест проверяет, что код моделей её не импортирует.

**Пропуск в `IC50_uM_VACV` — это та же запрещённая колонка.** В трейне
пропуск IC50 означает `SI = 0` в 100% случаев, в тесте таких строк 127.
Использовать этот факт нельзя без письменного разрешения организаторов.

Ещё запрещено: вручную искать и проставлять значения для молекул теста.
Данные собираются скриптами по вирусу и мишени, а не по списку теста.

## Факты про данные, проверенные на train_v2.csv

Не пересчитывайте их заново, не поверив: они зафиксированы тестами.

* 320 строк в трейне, 597 в тесте. Тест почти вдвое больше.
* `SI = CC50 / IC50` сходится на всех 237 строках, где обе величины есть.
* **Заглушка равна 0, а не 10000.** 81 строка без IC50 имеет `SI = 0`,
  плюс 2 строки без CC50. Всего нулей 83, то есть 25,9%.
  В старом файле `train.csv` заглушка была 10000 — выводы, сделанные по
  нему, недействительны.
* Медиана SI равна 1,84, максимум 36 066,7.
* Колонки `Culture` и `strain` **разрешены** и несут много сигнала:
  средний SI в BSC-40 равен 1497, в Vero 283, в HeLa 4. Все культуры из
  теста присутствуют в трейне.
* 30 строк теста соответствуют молекулам из трейна после стандартизации
  SMILES. `make_submission` подставляет им известные ответы.

## Главное свойство метрики

**Одна молекула создаёт 94% всей суммы квадратов.** Проверено:

| Что предсказываем | MSE на трейне |
|---|---|
| константа 213,4 | 4 254 705 |
| идеально угаданы все 83 нуля | 4 238 756 (−0,4%) |
| угадано всё, кроме одной молекулы | 4 042 277 (−5,0%) |
| угадана только эта одна молекула | 237 652 (−94,4%) |

Отсюда два правила.

**Не сжимайте прогноз и не обрезайте его сверху.** Занижение настоящего
гиганта стоит в 165 раз дороже завышения обычной молекулы: поставить 213
там, где правда 36 000, добавляет к MSE 2 145 000, а поставить 3000 там,
где правда 213, добавляет всего 13 000. Под MSE оптимален условный
средний, у него тяжёлый правый хвост. Осторожные варианты здесь проигрывают.

**Не сравнивайте модели по MSE на кросс-валидации.** Бутстрэп-интервал
примерно от 80 тысяч до 12 миллионов, у всех моделей он одинаковый.
Решения принимаются по `RMSE log` и `Spearman`, которые печатает
`make cv`. MSE нужна только для финального выбора между двумя кандидатами.

## Что даёт очки, а что нет

Стоит делать: узнавание известных высокоселективных противовирусных
(цидофовир, бринцидофовир, тековиримат, трифлуридин, аналоги нуклеозидов),
признаки близости к ним, сбор внешних данных ради этого.

Не стоит: Chemprop и предобученные эмбеддинги (320 молекул, метрика решается
пятью точками), подбор гиперпараметров (выигрыш неизмерим), погоня за
публичным лидербордом (он считается по 179 строкам).

## Команды

```
make env      создать окружение
make test     девять защитных тестов, обязательны перед слиянием
make cv       кросс-валидация, отчёт в reports/cv_results.md
make submit   обучение на всём трейне и сборка CSV
```

Интерпретатор — `./.venv/bin/python`, не системный. На macOS LightGBM и
XGBoost требуют libomp, поэтому используются только scikit-learn и RDKit.

## Правила работы с репозиторием

* В `main` напрямую не пушим. Это проверяет хук `.githooks/pre-push`,
  он же гоняет тесты перед отправкой. Включается через `make hooks`.
* Ветка под задачу: `r2/chembl-collector`, `r4/tail-features`.
* Перед пул-реквестом обязателен зелёный `make test`.
* Каждый трогает только свои файлы — таблица в `CONTRIBUTING.md`.
  Если нужен чужой файл, сначала напишите владельцу.
* Сиды не меняем, они в `src/config.py`.
* Каждый эксперимент — строка в `submissions/log.csv`: конфиг, CV, LB.
  Число без записи в журнал не считается результатом.

в таблице. Это приоритет номер один.
